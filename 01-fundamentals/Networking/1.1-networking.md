# Day 1: Networking — IP, DNS, TCP and UDP

## Goal

Understand how a client finds a server and how data travels between machines.

## One-page summary

- An **IP address** identifies a machine; a **port** identifies a program running on it.
- **DNS** converts a domain name into an IP address.
- **TCP** provides reliable, ordered communication. **UDP** is lightweight and does not guarantee delivery or order.
- Establishing a new TCP connection costs about **1 RTT**, so reusing connections is useful.
- **Flow control** protects the receiver; **congestion control** protects the network.

---

## 1. Networking layers

| Layer | Examples | Main job |
|---|---|---|
| Application | HTTP, DNS | Defines what the data means |
| Transport | TCP, UDP | Moves data between programs using ports |
| Network | IP | Routes data between machines |
| Link | Ethernet, Wi-Fi | Moves data across one local network hop |

**Important:** IP is best-effort. It does not guarantee that packets arrive. TCP adds reliability on top of IP.

## 2. IP addresses and ports

- **IP address:** identifies the destination machine.
- **Port:** identifies the application or service running on that machine.
- A connection can be identified by protocol, source IP, source port, destination IP and destination port.

### Common ports

| Service | Port |
|---|---:|
| HTTP | 80 |
| HTTPS | 443 |
| DNS | 53 |
| SSH | 22 |
| PostgreSQL | 5432 |
| MySQL | 3306 |
| Redis | 6379 |
| MongoDB | 27017 |

## 3. DNS — Domain Name System

DNS translates a human-readable domain, such as `www.example.com`, into an IP address that a computer can connect to.

### DNS hierarchy

`Root (.) → TLD (.com) → Authoritative name server (example.com) → Host (www)`

- **Root server:** directs the resolver to the correct TLD servers.
- **TLD server:** directs the resolver to the domain's authoritative name server.
- **Authoritative server:** stores the actual DNS records for the domain.
- **Recursive resolver:** does the lookup work and caches the answer. Examples include ISP resolvers and public resolvers such as `8.8.8.8` and `1.1.1.1`.
- **Stub resolver:** the client-side component on the device that asks the recursive resolver.

### How a cold DNS lookup works

1. The browser and operating system check their caches and local host entries.
2. The client asks a recursive resolver for the IP address.
3. The resolver asks a root server where to find the TLD server.
4. The resolver asks the TLD server for the domain's authoritative server.
5. The resolver asks the authoritative server for the DNS record.
6. The resolver returns the IP address and caches it for the record's TTL.

**Recursive query:** the client asks the resolver to find the final answer.

**Iterative query:** the resolver follows referrals from root to TLD to authoritative server.

### Important DNS records

| Record | Meaning |
|---|---|
| A / AAAA | Maps a name to an IPv4 / IPv6 address |
| CNAME | Alias pointing to another domain name |
| NS | Lists authoritative name servers |
| MX | Mail servers for a domain |
| TXT | Text data, often used for verification and email policies |
| SOA | Information about a DNS zone |
| PTR | Reverse lookup: IP address to name |

### TTL and caching

- **TTL (Time To Live)** tells DNS caches how long a record can be kept.
- Low TTL allows changes to be noticed sooner but causes more DNS lookups.
- High TTL reduces lookups, but old records may remain cached longer.
- Negative caching means failed lookups, such as `NXDOMAIN`, can also be cached.
- Before changing a DNS record for a migration, lower its TTL ahead of time.

### DNS transport

- DNS normally uses **UDP port 53**.
- DNS can use **TCP port 53** for large responses and zone transfers.
- **DoH** (DNS over HTTPS) and **DoT** (DNS over TLS) encrypt DNS queries.

### DNS in system design

- **Round robin:** return multiple IP addresses and rotate answers. It is a basic form of traffic distribution.
- **GeoDNS / latency routing:** return an IP based on the user's region or network latency.
- **Anycast:** multiple locations advertise the same IP; network routing sends users to a nearby location. CDNs and DNS infrastructure use it.
- **DNS failover:** health checks can help return a healthy destination, but cached records mean failover is not always instant.

**Limitation:** DNS is not a precise load balancer. Clients and resolvers cache answers, and one resolver may serve many users.

## 4. TCP vs UDP

| Feature | TCP | UDP |
|---|---|---|
| Connection | Connection-based | Connectionless |
| Delivery | Reliable: acknowledgements and retransmission | No delivery guarantee |
| Order | Ordered byte stream | Datagrams may arrive out of order |
| Control | Flow and congestion control | No built-in flow or congestion control |
| Header size | 20 bytes or more | 8 bytes |
| Data unit | Byte stream | Datagram |
| Typical uses | HTTP/1.1, databases, SSH, email | DNS, real-time voice/video, gaming, QUIC transport |

### When does UDP make sense?

Choose UDP when:
- Low delay matters more than receiving every packet. For example, a late video packet may no longer be useful.
- The application implements its own reliability, as QUIC does.
- The request/response is small, as with many DNS queries.

## 5. TCP three-way handshake

A TCP connection is established using three messages:

```text
Client                         Server
  | -------- SYN -------------> |
  | <------ SYN + ACK --------- |
  | -------- ACK -------------> |
  |                             |
  |       Connection ready      |
```

- The handshake synchronizes sequence numbers and confirms that both directions can communicate.
- It costs about **1 RTT** before normal data transfer begins.
- Three steps let the server confirm that the client received its SYN-ACK.

### Why three steps, not two?

The server needs confirmation that the client received its SYN-ACK. This also helps protect against stale or duplicate connection requests.

### SYN flood

A SYN flood happens when an attacker creates many half-open connections without sending the final ACK.

Possible defenses include:
- SYN cookies
- Rate limiting

---

## 6. TCP teardown and TIME_WAIT

A normal TCP close uses FIN and ACK messages in both directions:

```text
Side A                         Side B
  | -------- FIN ------------> |
  | <------- ACK ------------- |
  | <------- FIN ------------- |
  | -------- ACK ------------> |
```

The side that actively closes the connection usually enters **TIME_WAIT** for a period. This helps prevent delayed packets from interfering with a new connection.

**Possible problem:** many short-lived connections can consume local ports and resources.

**Common solution:** reuse persistent connections and connection pools.

---

## 7. How TCP provides reliability

TCP uses several mechanisms:

- **Sequence numbers:** identify byte positions and help restore order.
- **ACKs:** tell the sender which data has been received.
- **Retransmission:** sends data again when loss is detected by a timeout or duplicate acknowledgements.
- **Flow control:** the receiver advertises how much data it can accept. This protects the **receiver**.
- **Congestion control:** adjusts the sending rate based on network conditions. This protects the **network**.
- **Slow start:** TCP begins cautiously and increases its sending rate as acknowledgements arrive.

### Head-of-line blocking

TCP delivers bytes in order. If one packet is lost, later data on that connection waits until the missing data is recovered.

This is one reason HTTP/3 uses QUIC.

### Nagle algorithm and TCP_NODELAY

- **Nagle's algorithm** batches small writes to reduce the number of small packets.
- **TCP_NODELAY** disables Nagle's algorithm and can be useful for latency-sensitive applications.

---

## Common interview traps

- Saying "DNS is just a lookup" without mentioning its hierarchy, caching and TTL.
- Saying "TCP is reliable" without explaining sequence numbers, ACKs and retransmission.
- Mixing up flow control and congestion control:
  - Flow control protects the receiver.
  - Congestion control protects the network.
- Forgetting that DNS can use TCP as well as UDP.
- Forgetting that a new TCP connection costs about 1 RTT.
